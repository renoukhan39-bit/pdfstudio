# Core PDF toolkit

The website and API expose **16 tested prototype tools**: 14 PDF operations plus DOCX-to-PDF and PPTX-to-PDF conversion. This is not the complete Acrobat/Sejda roadmap and it is not a publicly hardened commercial service.

| Tool | API | Options and output |
| --- | --- | --- |
| Merge | POST `/api/tools/merge` | Multipart `files`, 2-10 PDFs; combined PDF |
| Split | POST `/api/tools/split` | `pages`: `1-3;4-6`; blank creates one PDF per page; ZIP |
| Extract | POST `/api/tools/extract` | `pages`: `3,1-2`; selected pages in requested order |
| Delete | POST `/api/tools/delete` | `pages`: `2,4`; all other pages retained |
| Reorder | POST `/api/tools/reorder` | `pages`: every page exactly once, such as `3,1,2` |
| Rotate | POST `/api/tools/rotate` | optional `pages`; `angle`: 90/180/270 clockwise |
| Compress | POST `/api/tools/compress` | lossless stream compression/object deduplication; original returned if no saving |
| Metadata | POST `/api/tools/metadata` | title/author/subject/keywords document-info fields |
| Extract text | POST `/api/tools/text` | optional pages; UTF-8 text; no OCR |
| Protect | POST `/api/tools/protect` | password 8-256 chars; AES-256 PDF |
| Unlock | POST `/api/tools/unlock` | known password; unencrypted output |
| Page numbers | POST `/api/tools/page-numbers` | optional pages; printable page/total footer |
| Text watermark | POST `/api/tools/watermark` | 1-120 printable ASCII text; optional pages |
| Crop | POST `/api/tools/crop` | margin 0-500 PDF points; visual crop only, not redaction |
| Word to PDF | POST `/api/tools/docx-to-pdf` | one validated DOCX; private Gotenberg 9.5.1; PDF |
| PowerPoint to PDF | POST `/api/tools/pptx-to-pdf` | one validated PPTX; private Gotenberg 9.5.1; PDF |

Except merge and Office conversion, send one multipart `file` plus a JSON-object string in `options`. DOCX/PPTX conversion needs only `file`. Output names are generated by the server rather than copied from uploaded names.

## Workspace

Choose a tool, upload/configure/process/download. PDF results up to 8 MiB can become the input for the next operation with **Use result in another tool**. DOCX/PPTX results automatically switch to a PDF tool when reused. This is browser-session state only; reloading clears it. Password fields clear after processing/switching.

## Limits and trust boundaries

- 8 MiB per input document, 40 MiB combined input and 200 PDF pages per operation.
- Raw HTTP body cap: 41 MiB with a 30-second upload deadline; output cap: 40 MiB.
- Active raw uploads are limited to two per service process.
- PDF/conversion processing is routed through a private worker in Compose. Local `uvicorn` development retains bounded child-process mode.
- Child work has a 25-second wall deadline; Linux children additionally get 20 CPU seconds, 768 MiB address-space limit and disabled core dumps.
- Compose worker/Gotenberg have no published ports, use the internal processing network, run read-only/non-root with dropped capabilities/resource limits, and CI verifies blocked public egress.
- Temporary multipart spools close on exit paths; there is no document database or intentional cloud history.

This isolation meaningfully reduces risk but is not a perfect hostile-document sandbox. Production still needs TLS, auth/rate limits, global quotas, retention policy, monitoring, container scanning and incident controls.

## Office conversion validation

DOCX/PPTX are ZIP-based OOXML and are treated as untrusted archives. The adapter bounds entry count, total/per-entry declared expansion and compression ratio; rejects unsafe/duplicate paths and encrypted packages; verifies the expected main OOXML part and content type; and never extracts the archive to the filesystem.

The Gotenberg client calls only the configured internal base URL plus the fixed `/forms/libreoffice/convert` route, disables environment proxies and redirects, rejects public converter hostnames, and does not accept user-provided converter URLs. Returned PDFs must have PDF MIME/signature, parse strictly, be unencrypted, fit the 40 MiB/200-page bounds and contain at least one page.

Compose pins Gotenberg 9.5.1 to `sha256:a0f596c2aeee6391c24ccf2953737971f13976b14d4240525a447f209185e2c8`. CI #51 proved both DOCX and PPTX synthetic conversions plus browser chaining before the immutable pin was accepted.

## Fidelity and honest boundaries

Generated PDFs are reopened and page counts verified; tests inspect ordering, rotations, text and encryption. Office smoke fixtures verify extracted expected text, but complex presentation/document fidelity (fonts, charts, SmartArt, tables, embedded media, complex scripts) needs a larger corpus.

Compression is lossless and may not shrink a PDF. Metadata editing is not hidden-data sanitization. Text extraction is not OCR. Crop/whiteout is not secure redaction. Password encryption is not a certificate signature. Changing a signed PDF may invalidate signatures.

Native existing-text editing, OCR, reverse PDF-to-Office conversion, image rendering, secure redaction and digital signing remain incomplete. Accounts, billing, AI and collaboration are frozen in Stages E/F. Original-code licensing remains an owner decision.
